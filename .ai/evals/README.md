# 功能评测

## 用途

功能评测用于证明某项产品能力满足 PRD（产品需求文档），而不是证明某个命令曾经成功运行。

每项非平凡功能至少留下一个最小可运行检查；跨界面、API（应用程序接口）、MCP（模型上下文协议）或磁盘的能力应同时保留读回证据。


## 回归评测模板

```text

同一调用链的相邻场景：
未覆盖风险：
```

## 评分方式

- 命令评分：确定性脚本、测试、类型检查、构建或文件校验。
- 人工评分：阅读、编辑、拖放、预览等人类体验路径。
- 模型辅助评分：内容质量、可读性或图片表达；不能替代来源、状态和文件正确性检查。

优先使用命令评分。需要人工或模型判断时，必须同时定义可观察输入、输出和失败条件。

## 通过与失败报告

```text
状态：通过 / 失败 / 部分通过 / 阻塞
已验证：
未验证：
失败或阻塞原因：
命令与退出码：
证据：
下一步：
```

禁止把“部分通过”写成“通过”，也禁止用截图替代真实对象、状态、接口和磁盘读回。

## 第一批应建立的评测

应用实现开始后，按以下顺序增加：

1. 人工完整链：浏览收集到发布包导出。
2. MCP（模型上下文协议）完整链：不点击界面完成同一业务链。
3. 双入口一致性：对象、版本、状态、错误和磁盘产物一致。
4. 审批失效：内容变化后旧批准不能生成发布包。
5. 存储透明：界面读数与真实目录、数量、容量一致。
6. 长期检索：规模数据下的全文、语义与组合筛选。
