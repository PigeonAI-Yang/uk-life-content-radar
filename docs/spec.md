# 自媒体桌面终端 SPEC（技术规格）

状态：用户已确认  
版本：第一版  
日期：2026-07-26  
上位契约：[PRD（产品需求文档）](spark/2026-07-26-ai-media-desktop-terminal-prd.md)

## 1. 技术目标

第一版采用 Electron（桌面应用框架）+ TypeScript（类型化脚本语言）单体。单体的含义是一个业务内核、一个 SQLite（本地数据库）和一份用户指定的业务根目录，不是界面与 MCP（模型上下文协议）各自实现业务逻辑。

界面通过 Electron（桌面应用框架）预加载桥接调用统一命令；MCP（模型上下文协议）通过 Windows（微软桌面系统）命名管道调用同一命令分发器。第一版不增加 Go（编程语言）服务、回环 HTTP（超文本传输协议）服务、微服务、事件总线、通用仓储接口或软件内 AI（人工智能）对话窗口。

### 1.1 已确认技术栈

| 层级 | 第一版选择 |
| --- | --- |
| 桌面与安装 | Electron（桌面应用框架）+ Electron Forge（桌面打包工具） |
| 编译与打包 | Webpack（网页打包工具）官方 TypeScript（类型化脚本语言）模板 |
| 界面 | React（界面框架）+ Fluent UI（微软流畅设计组件库）第九版 |
| 数据库 | SQLite（本地数据库）+ better-sqlite3（同步数据库驱动）+ FTS5（全文检索模块） |
| 数据访问 | 手写 SQL（结构化查询语言）和顺序迁移文件，不使用 ORM（对象关系映射） |
| 契约校验 | Zod（结构校验库） |
| 富文本 | Lexical（富文本编辑器内核） |
| 图片处理 | Sharp（图片处理库） |
| 内置浏览器 | Electron WebContentsView（网页内容视图） |
| MCP（模型上下文协议） | 官方 TypeScript SDK（类型脚本开发包）与 stdio（标准输入输出） |
| 内部进程通信 | Windows Named Pipe（微软系统命名管道） |
| 自动验证 | Vitest（单元测试工具）+ Playwright（界面自动化工具） |

第一版不使用 Vite（前端构建工具）、Next.js（全栈网页框架）、Redux（集中式状态管理库）、Zustand（轻量状态管理库）或通用插件框架。前端状态先使用 React Context（界面上下文）与 `useReducer`（状态归并钩子）；只有真实跨页面状态问题证明不足时再增加状态库。

## 2. 运行边界

```text
React（界面框架）渲染界面 ─┐
                           ├─ 统一命令与查询 ─ SQLite（本地数据库）
MCP（模型上下文协议）适配器 ─┘                  └─ 用户业务根目录
```

- Electron（桌面应用框架）主进程持有唯一数据库连接、文件操作能力、浏览器容器和任务执行器。
- 界面与 MCP（模型上下文协议）适配器只做序列化、调用和错误映射，不直接写数据库或业务文件。
- 关闭主窗口默认隐藏到系统托盘，主进程与 MCP（模型上下文协议）能力继续运行；用户执行“完全退出”后停止任务。再次启动时，遗留运行中任务标记为“已中断”。
- 用户最终批准仅能在界面完成；MCP（模型上下文协议）可请求批准、读取批准状态和在批准后打包，但不暴露批准命令。

## 3. 最小源码结构

```text
src/
  main/             应用启动、窗口、托盘、浏览器与传输适配
  business/         commands（命令）、queries（查询）与业务规则
  storage/          SQLite（本地数据库）、文件、检索与图片处理
  tasks/            持久任务执行
  mcp/              MCP（模型上下文协议）薄适配器
  renderer/         React（界面框架）页面与组件
  contracts/        输入、输出与错误结构
```

不预建可替换实现、插件系统或通用工作流引擎。出现第二个真实实现后再抽象。

## 4. 数据模型

| 数据表 | 关键内容 |
| --- | --- |
| `accounts` | 名称、定位、受众、语气、禁用表达、平台身份、默认模板和版本 |
| `sources`、`source_snapshots` | 来源、规范地址、原文快照与采集时间 |
| `excerpts`、`notes` | 原文片段、上下文与笔记 |
| `assets`、`asset_versions` | 原始素材、派生版本、尺寸、来源、文件信息、内容摘要和文件状态 |
| `content_projects`、`content_versions` | 账号归属、公共草稿、平台版本、父版本和正文内容摘要 |
| `content_source_refs`、`content_asset_refs` | 内容与资料、素材的引用关系及图片顺序 |
| `saved_views` | 各业务库内的已保存组合筛选 |
| `tasks` | 任务状态、进度、结果、错误和临时产物结果 |
| `approval_requests`、`approvals` | 批准请求、确定指纹、批准人和时间 |
| `packages`、`package_files` | 账号归属、平台发布包、清单、真实文件及内容摘要 |
| `idempotency_records` | 命令、幂等键、请求摘要和原结果 |
| 全文索引表 | SQLite FTS5（全文检索模块）索引 |

所有业务对象使用稳定标识与时间戳。重命名、文件迁移、归档和恢复不得改变稳定标识。正文修改创建新版本或提交 `expected_version`（预期版本）；版本不匹配返回冲突，不静默覆盖。内容项目与发布包必须归属一个账号；资料和素材可跨账号引用，不复制底层文件。第一版不引入知识图谱、事件溯源、万能对象表或文件夹树。

## 5. 文件存储

用户首次启动选择业务根目录：

```text
<业务根目录>/
  sources/
  assets/original/
  assets/derived/
  packages/
  .content-terminal/index.sqlite
  .content-terminal/tmp/
```

- 根目录只允许首次初始化前选择。第一版已有数据后只读显示，不提供普通“更改根目录”命令。
- 设置页显示数据库与临时目录的真实位置、数量、容量及相对上次成功扫描的数量和容量变化。
- 外部文件默认复制入业务根目录，避免原位置移动后失联；不提供“仅引用外部路径”模式。
- 导入与生成采用：数据库记录待处理 → 同卷临时文件 → 校验 → 原子改名 → 数据库完成态。
- 数据库与文件系统不是同一事务。启动时扫描待处理记录：完整产物读回后补完成；残缺产物清理并标记失败或已中断。
- 第一版只有归档与恢复，不提供任何永久删除业务命令或界面入口。
- 文件型对象在读取、引用、处理和打包前校验存在性、字节数与 SHA-256（安全哈希算法）摘要。外部删除标记为 `missing`（文件丢失），外部改写标记为 `modified`（外部修改），不得继续沿用完成状态。
- 提供按需一致性扫描任务，只报告并更新文件状态，不自动删除或覆盖用户文件。

## 6. 统一业务契约

每个命令返回：

- 对象稳定标识；
- 当前版本或更新时间；
- 当前状态；
- 产生的关系；
- 文件型对象的真实绝对路径、大小和修改时间；
- 长任务的任务标识。

每个写操作必须能按稳定标识查询读回。批量命令逐项返回成功和失败；部分成功的整体状态为 `partial`（部分成功）。

核心命令域：

| 业务域 | 写命令 | 查询 |
| --- | --- | --- |
| 收集 | 按浏览器标签收集网页、摘录、保存图片、接管下载、导入文件、写笔记并选择落点 | 标签、来源、快照、重复候选与落点回执 |
| 资料、摘录、笔记 | 创建、更新、关联、移除关联、归档、恢复、保存视图 | 读取、检索、筛选、阅读上下文与使用记录 |
| 内容 | 创建选题、保存版本、关联或移除资料素材、从历史版本创建、生成平台版本 | 项目、历史版本、引用、平台差异与账号归属 |
| 素材 | 导入、归档、恢复、裁剪、缩放、压缩、尺寸转换、文字叠加、导入外部修改版本 | 读取、检索、筛选、原图、版本、真实路径与使用记录 |
| 发布包 | 创建预览、请求批准、生成已批准包 | 候选、指纹、批准状态、清单、文件与账号归属 |
| 账号 | 创建、更新 | 读取、检索、平台身份、风格、模板和使用关系 |
| 任务 | 创建、取消 | 状态、进度、结果与错误 |
| 设置 | 首次初始化根目录、更新平台模板与默认导出目录 | 根目录、存储统计、增长、索引状态与导出设置 |

## 7. MCP（模型上下文协议）对等规则

- 工具与统一命令或查询一对一映射，不另写业务分支。
- 阶段 0 即交付可被 Codex（代码智能体）发现和调用的真实 MCP（模型上下文协议）服务、注册信息、连接生命周期与调用回执；内部管道测试不能替代真实客户端验收。
- 创建、采集、导入、图片处理和打包接受调用方幂等键，唯一作用域为“调用方、命令、幂等键”。
- 规范化请求摘要与唯一记录在同一数据库事务内原子占位。相同键和相同参数返回原结果；相同键但不同参数返回冲突；执行中的重复请求返回同一任务标识。并发失败与重试保留同一记录和明确状态。
- MCP（模型上下文协议）不暴露最终批准工具，不直接操作磁盘或数据库。
- 每个阶段均以同一输入分别走界面和 MCP（模型上下文协议），比较对象结构、版本、关系、错误与磁盘产物。

## 8. 审批与发布包

批准指纹绑定：

```text
内容版本标识与正文摘要 + 有序素材版本标识、字节数与文件摘要
+ 账号配置版本 + 平台 + 渲染模板版本
```

任一正文、图片内容、图片版本、图片顺序、账号渲染配置或模板变化都会产生新指纹，旧批准自动失效。打包开始时冻结批准快照，复制每个文件前后校验摘要；任何不匹配均返回批准失效，不生成完成发布包。

每个平台独立生成结果，允许部分成功。每个包包含 `manifest.json`（清单文件），记录正文文件、图片文件、顺序、尺寸、来源、内容版本、素材版本和批准指纹；生成后逐项从磁盘读回校验。

## 9. 任务状态

任务状态仅使用：

`queued`（已排队）、`running`（运行中）、`succeeded`（成功）、`partial`（部分成功）、`failed`（失败）、`cancelled`（已取消）、`interrupted`（已中断）。

任务持久保存触发者、进度、结果对象标识、可理解错误和临时产物处理结果。应用启动时将遗留的运行中任务改为已中断；只有可安全重建的索引任务允许用户重新执行。

取消只在最终提交点之前生效：执行器收到取消后停止后续写入、清理或记录临时产物并将状态改为已取消；提交完成后再取消返回“任务已完成”。取消与完成竞争必须由同一数据库事务决定，已取消任务不得存在完成对象。

## 10. 检索与规模

- 资料库阶段即使用 SQLite FTS5（全文检索模块）与普通索引完成关键词、组合筛选、对象类型分组和保存视图，不使用临时内存筛选。
- 分页使用稳定游标，排序尾键包含稳定标识，验收翻页不重不漏。
- 语义检索不得伪装成全文检索。实施前必须完成独立决策门：本地嵌入模型、授权、体积、向量索引、安装包增量与 10 万条数据基准全部明确后才进入实现。
- 未通过语义检索验收时，第一版状态只能是未完成。

规模基准沿用 PRD（产品需求文档）第 11 节。测试报告必须记录参考设备、数据生成种子、冷缓存与热缓存、三次运行结果和中位数。

| 对象类型 | 可索引字段 | 必须筛选维度 |
| --- | --- | --- |
| 资料、摘录、笔记 | 标题、正文、摘要、来源与标签 | 主题、地区、人群、来源、时间、状态、归档 |
| 内容与历史版本 | 标题、正文、平台字段 | 账号、平台、主题、时间、状态 |
| 素材元数据 | 名称、说明、来源与标签 | 账号使用关系、类型、尺寸、时间、状态 |
| 发布包 | 标题、正文摘要、来源清单 | 账号、平台、批准状态、时间 |
| 账号 | 名称、定位、受众、语气、禁用表达 | 平台与状态 |

全局搜索包含归档对象并明确标识；业务库默认隐藏归档对象。规模数据为每类对象和每个筛选维度植入固定哨兵记录。

## 11. 浏览器与图片

- 内置浏览器采用 Electron WebContentsView（网页内容视图），由主进程托管多标签页与登录态。
- 浏览器提供地址栏、网页内查找、标签列表和下载接管。每个标签具有稳定 `tab_id`（标签标识）。
- 收集命令必须指定标签标识，从对应会话读取地址、标题、选区快照、图片或下载响应；登录态保护资源由主进程使用该标签会话读取，再进入统一导入命令。
- 收集完成返回资料库、素材库或内容项目的明确落点与对象标识。
- 图片处理库在实现切片开始前做一个真实中文字体叠加与五项处理实验，再决定依赖；不得在文档阶段假定某个库已经通过。
- 字体仅使用系统已安装且用户选择的字体；发布包清单记录字体名称，不复制无授权字体。

## 12. 错误契约

稳定错误码至少包含：对象不存在、输入无效、版本冲突、幂等冲突、文件不可读、文件不可写、文件丢失、文件外部修改、任务失败、任务已取消、未批准、批准失效、磁盘空间不足、根目录已初始化。

错误返回业务描述、关联对象或任务标识、可恢复建议；不得仅返回“失败”，也不得把技术堆栈作为人类主错误。

## 13. 质量与安装验收

- 自动检查：类型、代码检查、最小业务测试、构建、界面关键路径和 MCP（模型上下文协议）对等实验。
- 失败实验：无写权限、磁盘不足、处理中断、应用重启、幂等冲突、版本冲突、批准失效和单平台打包失败。
- 真实安装：在干净 Windows 11（微软桌面系统）用户环境验证安装、启动、根目录选择、MCP（模型上下文协议）注册、关闭窗口后调用、重启读回、发布包磁盘校验和卸载不删除业务根目录。

## 15. 内容事业合伙人扩展

### 15.1 单体边界

内容生意工作台继续复用现有 Electron（桌面应用框架）单体、唯一业务分发器、唯一 better-sqlite3（同步数据库驱动）连接、用户业务根目录和 Windows Named Pipe（微软系统命名管道）。不增加 CRM（客户关系管理系统）服务、OCR（光学字符识别）服务、HTTP（超文本传输协议）服务或新状态管理库。

截图理解由外部 Codex（代码智能体）完成；应用只负责接收原始文件路径、经过 Zod（结构校验库）验证的提取结果、用户确认状态和对象关系。

### 15.2 SQLite 对象

手写迁移建立：

- `products`、`product_versions`：产品当前状态和不可覆盖版本文件；
- `strategy_proposals`、`strategy_versions`：策略提案与经人类批准的正式版本；
- `leads`：客户来源、阶段、需求、意向和下一步；
- `conversation_records`：私信、微信、口述材料原件与提取结果；
- `deals`：成交金额或未成交原因及内容洞察；
- `post_metrics`：带观察时间和来源类型的平台表现；
- `intelligence_candidates`：定时扫描候选、核验、时效、重复关系和失败来源。

客户阶段只使用 `new_message`、`need_understood`、`wechat_added`、`negotiating`、`won`、`lost`。沟通原件无法确认客户时允许 `lead_id` 为空并标记 `pending`，不得猜测合并。

### 15.3 业务文件

业务根目录增加：

```text
business/products/<product-id>/<version>.json
business/strategies/<account-id>/<version>.json
customers/<lead-id>/summary.json
conversations/<conversation-id>/<original-file>
intelligence/<candidate-id>/candidate.json
```

文件型对象读回绝对路径、大小、修改时间、保存摘要、实际摘要和 `present | missing | modified`。原始截图、聊天文本、产品版本和策略版本不覆盖。

### 15.4 统一命令

首批命令：

- `product.create|get|update|list`
- `strategy.propose|get|list|approve`
- `lead.create|get|update|list`
- `conversation.import|get|confirm|list`
- `deal.record|get|list`
- `post_metrics.record|list`
- `business.snapshot`
- `intelligence.create_candidate|get|list`

创建、导入和记录命令接受调用方与幂等键；更新命令使用期望版本。`strategy.approve` 与 `approval.approve` 一样只允许人类界面调用，MCP（模型上下文协议）注册时排除。

### 15.5 经营快照

`business.snapshot` 是跨会话恢复查询，返回：

- 当前产品和经批准策略；
- 最近内容与资讯候选；
- 各阶段客户数量和需要跟进的客户；
- 最近成交与未成交原因；
- 待确认沟通材料；
- 待批准策略提案和发布包；
- 最后成功扫描时间、失败来源和明确数据缺口。

快照只汇总真实对象，不让模型生成的文字代替数据库事实。
