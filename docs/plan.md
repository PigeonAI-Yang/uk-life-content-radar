# 自媒体桌面终端 PLAN（实施计划）

状态：用户已确认  
版本：第一版  
日期：2026-07-26  
依据：[PRD（产品需求文档）](spark/2026-07-26-ai-media-desktop-terminal-prd.md)、[SPEC（技术规格）](spec.md)、[UI（用户界面）视觉规范](ui-visual-spec.md)

可执行拆解与状态追踪见 [TASK（任务）台账](tasks.md)。

## 1. 实施原则

不按“先写全部前端、再写后端、最后补 MCP（模型上下文协议）”拆分。每个切片都同时交付：

```text
界面动作 → 统一命令或查询 → SQLite（本地数据库）与磁盘产物
MCP（模型上下文协议）动作 ────────────────┘
```

每片必须具备真实输入、界面入口、MCP（模型上下文协议）工具、对象与状态读回、失败实验和一个最小自动检查。任一入口缺失均不算完成。

## 2. 阶段 0：可执行工程壳与契约

交付：

- Electron Forge（桌面打包工具）官方 Webpack（网页打包工具）+ TypeScript（类型化脚本语言）模板，接入 React（界面框架）与 Fluent UI（微软流畅设计组件库）第九版。
- better-sqlite3（同步数据库驱动）、手写 SQL（结构化查询语言）迁移与 FTS5（全文检索模块）可运行实验。
- 主进程、渲染界面、业务命令与查询、SQLite（本地数据库）迁移、用户根目录选择。
- 预加载桥接、Windows（微软桌面系统）命名管道及可由 Codex（代码智能体）发现调用的真实 MCP（模型上下文协议）服务与注册。
- 最小持久任务执行、状态转换、取消提交点、启动中断恢复和临时产物处置。
- 统一错误、稳定标识、乐观版本、幂等原子占位和文件摘要结构。
- 现有总门禁接入类型检查、代码检查、最小测试与构建。

可证伪验收：

- 同一“创建内容项目”命令分别从界面与 MCP（模型上下文协议）执行，结构、状态与读回规则一致。
- 使用真实 Codex（代码智能体）客户端发现工具、调用命令并读回结果；内部适配器测试不能替代。
- 根目录不可写时创建失败，数据库不得出现完成对象。
- 两个入口使用同一预期版本并发修改，只有一个成功，另一个明确版本冲突。
- 同一幂等键并发导入只创建一项记录；同键异参明确冲突。
- 任务运行时终止应用，重启后状态为已中断且临时产物结果可读回。
- 首次选择根目录后，普通设置命令不能切换到另一目录。

退出条件：真实开发应用可运行，双入口确实调用同一业务内核，不是两套示例。

## 3. 阶段 1：单平台最小发布闭环

先只做小红书图文，用最短闭环证明架构：

- 导入一个本地资料文件。
- 创建最小账号，创建归属该账号的内容项目并保存公共草稿版本。
- 关联资料与图片。
- 生成人工可读预览。
- 用户批准确定版本。
- 生成真实发布包与 `manifest.json`（清单文件）。

可证伪验收：

- 未批准打包失败；批准后成功；修改正文或图片顺序后旧批准失效。
- 清单逐项核对真实路径、大小、顺序与尺寸。
- 相同幂等键重复导入只产生一个对象和一份文件；同键异参返回冲突。
- 打开真实目录、复制正文并按清单顺序取图；复制内容与清单正文一致。
- 批准后原地改写派生图片，打包因摘要不一致返回批准失效。

退出条件：界面完整链和纯 MCP（模型上下文协议）链均通过，只有批准必须由用户在界面完成。

## 4. 阶段 2：浏览、资料库与引用写作

交付：

- 内置浏览器、多标签页、当前页收藏、文本摘录、图片与文件收集。
- 资料库全宽列表、宽屏阅读器、SQLite FTS5（全文检索模块）、组合筛选、稳定游标、归档恢复与保存视图。
- 编辑器大纲、正文、统一右侧资源槽、引用回看与版本历史。
- 资料、摘录和笔记的独立读取、更新、检索、归档、恢复与跨项目复用。
- 地址栏、网页内查找、登录态、重复网址提示和原文上下文保留。

可证伪验收：

- 键盘完成搜索、筛选、选中、摘录、加入内容、插入引用和保存版本。
- 分别验证网页、选中文本、图片、下载文件四个收集入口及资料库、素材库、内容项目三种落点回执。
- MCP（模型上下文协议）按标签标识收集登录态保护资源，结果与界面入口同构。
- 1280 与 1600 宽度分别通过抽屉与双栏规则，无大空区。
- 删除引用不删除资料；重新生成平台版本不覆盖人工修改。
- 重命名、文件迁移、归档、恢复前后稳定标识不变。
- 网页收集中断或来源不可读时，不留下完成快照。
- 用阶段性规模样本验证全文索引和稳定游标，不允许先用临时内存筛选。

## 5. 阶段 3：素材库与图片版本

实施前先用真实中文字体完成裁剪、缩放、压缩、平台尺寸转换和文字叠加实验，再选图片依赖。

交付：

- 素材网格与列表、来源、尺寸、使用记录、原图与版本。
- 五项基础处理和可再次编辑的文字叠加参数。
- 各平台独立图片顺序和尺寸版本。
- 外部处理结果导入并关联原素材。

可证伪验收：

- 每次处理产生新文件和新版本，原图哈希不变。
- 处理中断、磁盘不足或无写权限时不得出现成功状态。
- 相同幂等键返回同一图片版本。
- 外部删除或改写已完成图片后，读取分别返回文件丢失或外部修改，不保留完成状态。

## 6. 阶段 4：三平台发布包

实施前核对三个平台当前图文约束与来源版本。

交付：

- 小红书、抖音图文、微信公众号独立正文与图片版本。
- 完成账号定位、受众、语气、禁用表达、三个平台身份与默认模板；各内容和发布包归属指定账号。
- 三个平台预览、批准请求、批准指纹、失效提示。
- 各平台独立打包、真实目录、来源清单和审核记录。
- 微信公众号最低可复制长文预览。

可证伪验收：

- 一个失败平台不污染其他平台，整体明确为部分成功。
- 应用预览、清单与磁盘内容一致。
- MCP（模型上下文协议）无法执行最终批准。
- 小红书逐项核对标题、正文、话题标签、封面、正文图片、顺序、预览、来源清单和审核记录。
- 抖音逐项核对标题或说明、正文、话题标签、封面、图文图片、顺序、预览、来源清单和审核记录。
- 微信公众号逐项核对标题、摘要、正文、封面、正文插图、顺序、长文预览、来源清单和审核记录。
- 每个平台的应用预览、清单字段和磁盘文件逐项一致。
- 两个账号引用同一资料与素材时，底层文件只有一份。

## 7. 阶段 5：任务中心与存储透明

交付：

- 在阶段 0 持久任务内核上提供任务列表、进度、取消、失败、部分成功和已中断读回。
- 根目录数量、容量，以及相对上次成功扫描的数量和容量增长。
- 工作台首屏的继续创作、待处理、待审核和失败项。

可证伪验收：

- 任务运行中完全退出应用，再启动后显示已中断而非成功。
- 提交前取消后执行器停止，不再写入文件，不存在完成对象；重启后仍为已取消。提交后取消返回任务已完成。
- 关闭窗口但不完全退出时，MCP（模型上下文协议）仍能执行并在界面重开后读回。
- 设置页统计与真实磁盘扫描一致。
- 导入固定文件前后各成功扫描一次，增长数值等于真实数量和字节变化。
- 界面、业务命令和 MCP（模型上下文协议）均不存在永久删除能力。

## 8. 阶段 6：长期检索与规模

交付：

- 跨资料、摘录、笔记、内容版本、素材元数据、发布包和账号的全局检索。
- 确定性规模数据生成器：10 万资料、3 万图片版本、5000 文案、1000 发布包、20 账号。
- 语义检索决策实验和实现；若模型、授权、体积、索引或性能未过门禁，则第一版保持未完成。

可证伪验收：

- 参考设备、固定数据种子、冷缓存与热缓存各运行三次并记录中位数。
- 关键词组合筛选首屏小于 2 秒，语义首屏小于 5 秒。
- 性能计时以安装应用中提交搜索到首屏可操作为准，同时记录数据库查询、界面渲染、峰值内存和连续翻页。
- 游标遍历无重复、无遗漏。
- 查找指定旧资料、历史文案、已用素材和归档对象不依赖逐页翻阅。
- 地区、人群、自由标签、来源、时间、账号、平台、状态和归档哨兵记录均可唯一命中。

## 9. 阶段 7：完整桌面交付

交付：

- 九个一级模块的完整可达路由与必要状态。
- 逐行执行 UI（用户界面）视觉规范第 8.1 节页面状态矩阵；每项保存可达入口、对应截图和关键操作回执，不以静态占位图代替真实状态。
- 四档窗口截图、键盘链、缩放与可访问性检查。
- Windows（微软桌面系统）安装包和真实 MCP（模型上下文协议）安装态注册复验。
- 干净机器验收记录、应用版本、安装文件摘要、运行进程与真实数据读回。

可证伪验收：

- 在干净 Windows 11（微软桌面系统）用户环境完成安装、启动、根目录选择、收集、写作、图片处理、批准、三平台打包、重启读回。
- 记录安装二进制身份和 MCP（模型上下文协议）注册目标；关闭窗口后从外部 Codex（代码智能体）调用，重开窗口读回；完全退出后调用必须明确拒绝。
- 卸载应用不删除用户业务根目录。
- 开发服务器、单张截图或绿色单元测试均不能替代安装应用完整链。

## 10. 阶段 8：内容事业合伙人系统

依据：[内容事业合伙人系统设计](spark/2026-07-28-content-business-partner-system-design.md)。

1. 先建立资讯扫描、候选、核验、重复关系、资料、内容和任务的 SQLite（本地数据库）对象及真实业务文件目录。
2. 再实现扫描结果、候选整理、资料沉淀、选题和内容衔接的统一业务命令。
3. 再通过 MCP（模型上下文协议）暴露同语义能力，并保留明确的人工决策边界。
4. 再实现“情报”工作区，使最新候选、时效、影响、来源失败和最后成功时间成为主界面。
5. 软件能力真实可用后创建并安装内容事业合伙人总控 Skill，使新会话恢复最新情报、资料、内容供给和任务。
6. 最后用真实外部资讯、部分扫描失败、资料与内容转化、真实 MCP、新会话和重启读回完成 BIZ-008；发布、私信和成交是可选下游，不作为阻塞条件。

## 11. 阶段 9：Pi Agent 自动接力

依据：[Pi Agent 执行内核接入设计](spark/2026-07-28-pi-agent-runtime-design.md)。

1. 先锁定 Pi SDK，完成自定义兼容 API、CockpitTools 导入、订阅登录、Codex 登录探测、OAuth（开放授权）与设备码的认证顺序和失败实验。
2. 再复用现有持久任务实现串行 Pi Runner、MCP（模型上下文协议）工具链、取消、中断与重启恢复。
3. 再将策略批准和最终发布批准后的允许动作接入 Pi 任务，并在现有任务与设置页面显示状态。
4. 最后使用真实 CockpitTools 或用户配置的兼容 API 与真实 Windows（微软桌面系统）安装应用完成自动接力验收；订阅登录继续作为可选入口。

Pi 不直接访问业务数据库或业务文件，不获得策略批准或最终发布批准工具，不自动发布到平台。

## 12. 每阶段报告格式

每阶段只按以下证据报告：

1. 本阶段输入与真实运行入口。
2. 界面动作、MCP（模型上下文协议）工具及共同业务命令。
3. 数据库对象、状态和磁盘产物。
4. 写后读回与失败实验结果。
5. 自动门禁与安装应用门禁。
6. 已知未验证项、部分成功和阻塞。

## 13. 第一版停止条件

只有 PRD（产品需求文档）第 14 节全部通过才可宣布第一版完成。任何语义检索、双入口对等、审批门禁、真实磁盘包、规模基准或安装应用链缺失，状态均为部分完成或阻塞。
