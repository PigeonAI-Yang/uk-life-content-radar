# 内容事业合伙人系统设计

状态：讨论中  
日期：2026-07-28  
适用项目：自媒体桌面终端

## 1. 背景

自媒体桌面终端不能只被理解为一套需要用户逐页操作的软件，也不能只依赖一份讲解按钮和基础命令的操作 Skill。

目标形态由三部分共同组成：

1. Skill：提供经营方法、判断原则与协作规则；
2. 应用终端：保存真实业务状态与长期内容资产；
3. 外部 Agent（Codex）：基于当前事实进行动态判断并完成执行。

三者组合后，用户不必亲自管理每一个操作步骤，而是以业务负责人身份确定方向、批准战略和最终发布。Codex 作为内容事业合伙人，使用终端持续经营用户的内容业务。

## 2. 已确认的愿景

完整系统的愿景是：

> 由用户领导、Codex 执行，以 Skill 提供经营方法、以终端保存业务事实的个人内容商业经营系统。

系统不是单纯追求内容数量、流量或基础自动化，而是以用户自有产品和服务的商业结果为最高目标，通过内容持续建立信任、获得目标客户并推动收入。

## 3. 已确认的产品目标

### 3.1 合伙人身份

总控 Skill 的角色是“内容事业合伙人”，而不是软件操作员、写作助手或任务路由器。

它必须：

- 理解用户为什么经营账号以及希望获得什么商业结果；
- 从产品、目标客户和客户需求倒推内容工作；
- 判断当前最重要的商业问题，而不是等待用户逐项派发操作；
- 组织研究、选题、内容、素材、多平台适配、发布准备与复盘；
- 让资料、洞察、内容和经营反馈成为可持续复用的长期资产；
- 主动挑战假设并提出策略调整，但不越过用户的战略主权。

### 3.2 商业结果优先

最高目标是通过内容销售用户自己的产品或服务。

默认经营链为：

> 产品与服务 → 目标客户 → 客户问题与购买动机 → 信任建设 → 内容与行动引导 → 咨询与成交反馈 → 策略调整

流量、内容数量和资料规模属于过程指标。它们只有在支持目标客户、信任、咨询或收入时才具有经营价值。

### 3.3 完整商业闭环

内容事业合伙人负责理解完整商业闭环：

- 产品与服务；
- 目标客户；
- 客户问题、需求和异议；
- 内容策略与账号定位；
- 研究、选题和生产；
- 多平台分发准备；
- 咨询与成交反馈；
- 基于真实结果的经营复盘。

Codex 不替用户完成资金行为或最终成交，但必须理解真实咨询和成交反馈，才能判断内容是否有效。

### 3.4 主动经营

当用户只说“开始工作”时，总控 Skill 应当：

1. 读取终端中的业务现状；
2. 找出当前最重要的商业问题或约束；
3. 提出本轮目标与判断依据；
4. 在既定战略范围内主动执行；
5. 仅在战略选择、缺失关键事实和最终发布时请求用户决策；
6. 将过程与结果写回终端，形成下一轮可延续状态。

不得凭空编造价格、客户反馈、成交数据或其他商业事实。缺少关键事实时必须明确向用户索取。

## 4. 已确认的系统架构

采用“总控 Skill + 专业子 Skill + 应用终端 + 外部 Codex”的组合，而不是单一超级 Skill，也不把所有经营判断固化进应用代码。

### 4.1 用户

用户拥有以下主权：

- 决定卖什么；
- 决定服务谁；
- 批准账号定位与正式经营策略；
- 批准产品、价格和转化路径的重大变化；
- 批准最终发布包。

### 4.2 总控 Skill

总控 Skill 负责：

- 读取和理解商业现状；
- 诊断经营瓶颈；
- 确定阶段目标和下一最佳行动；
- 选择并编排专业子 Skill；
- 检查专业结果是否服务商业目标；
- 要求 Codex 将经营结果写回终端；
- 在越过授权边界前请求用户批准。

总控 Skill 必须拥有完整经营判断框架，不能退化为只按关键词转发任务的路由器。

### 4.3 专业子 Skill

专业子 Skill 提供某一环节的专业能力，例如：

- 英国生活资讯研究与事实核验；
- 产品与客户研究；
- 选题策划；
- 平台文案创作；
- 图片与封面制作；
- 发布包准备；
- 商业反馈复盘。

专业子 Skill 对本环节的质量负责，但不能自行改变正式商业策略。

### 4.4 外部 Agent（Codex）

Codex 负责：

- 加载总控 Skill；
- 读取终端中的当前业务事实；
- 进行情境化推理；
- 调用专业子 Skill；
- 通过 MCP 操作终端；
- 完成写后读回；
- 把结果、失败、证据和待决策项反馈给用户；
- 把本轮经营状态写回终端。

Codex 的聊天上下文不是正式、长期的经营记忆。

### 4.5 应用终端

终端是唯一可核验的业务账本，保存：

- 账号、资料、摘录、内容、素材、版本、发布包和任务；
- 产品与服务；
- 目标客户；
- 客户问题、需求和异议；
- 转化目标；
- 咨询与成交反馈；
- 策略版本、批准记录和经营决策；
- 真实文件、对象关系、执行状态和错误。

Skill 不硬编码用户的动态业务事实。个人策略和经营反馈必须进入终端，确保更换 Codex 会话或未来更换 Agent 后仍可延续。

## 5. 已确认的主权边界

- Codex 可以主动诊断、研究、规划和执行既定战略内的工作。
- Codex 可以提出账号定位、产品、价格或转化路径的调整建议。
- 未经用户批准，建议不能写成正式经营策略。
- 最终发布批准只能由用户完成。
- 专业子 Skill 不得自行提升权限或绕过总控 Skill 的经营约束。
- 每轮工作必须在终端产生可读回的业务状态，不能只产生聊天回复。

## 6. 已确认的设计原则

1. 商业结果优先于内容数量和表面流量。
2. 主动经营优先于等待逐项指令。
3. 终端事实优先于聊天记忆和模型推测。
4. 长期资产积累必须服务真实经营，而不是为了堆积资料。
5. 执行可以高度自主，战略变化必须人工批准。
6. 总控 Skill 负责经营判断，专业 Skill 负责环节质量。
7. UI 与 MCP 必须继续调用同一业务内核并操作同一份数据。
8. 用户保留最终方向、策略与发布主权。
