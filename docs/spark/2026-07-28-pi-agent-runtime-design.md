# Pi Agent 执行内核接入设计

状态：用户已确认方案  
日期：2026-07-28  
产品：自媒体桌面终端

## 1. 决策

自媒体桌面终端固定采用 Pi 作为后台 Agent 执行内核，不建设通用 Agent 框架，也不保留多执行器切换层。

当前 Codex 对话仍是用户讨论方向、提出要求和共同判断的入口；终端仍是用户与 Agent 共享的业务工作台。Pi 补足终端事件无法主动驱动工作的缺口，使人工批准、待办和定时事件能够直接转成后台执行任务。

软件内增加固定右侧、可收起的 Pi 协作栏；它只创建和读取既有 `agent.execute` 任务，不增加独立聊天服务或第二套历史。

Pi 情报任务同时加载内容情报总控 Skill、英国生活内容雷达 Skill 与来源地图，并使用受控 `web_search`、`web_read` 完成发现和原文核验。所有候选、扫描状态和失败来源仍经终端 MCP 写回统一业务内核。

## 2. 目标

第一条必须闭合的链路是：

```text
用户在终端批准经营策略
→ 同一业务事务创建 Pi 执行任务
→ Pi 读取已批准策略和经营快照
→ Pi 通过终端 MCP 执行业务命令
→ 产物、状态和错误写回终端
→ 用户在终端查看结果或继续批准
```

相同机制后续用于发布包批准后的构建、内容生产、资料整理、客户跟进建议和定时资讯处理。第一批实现只覆盖已有产品契约中能够通过现有 MCP 完成的动作，不增加自动发布或新的业务模块。

## 3. 技术选择

使用 `@earendil-works/pi-coding-agent` 的 Node.js/TypeScript SDK，嵌入 Electron 主进程。

不采用：

- Pi RPC 子进程：第一版不承担额外的进程协议、安装路径和版本协同。
- 用户全局安装的 Pi：不能保证干净 Windows 环境、版本一致和卸载行为。
- 通用 Agent 适配接口：当前已经确定长期使用 Pi，没有第二种实现。

Pi 随 Windows 应用安装包交付，版本固定在项目依赖中。

## 4. 运行边界

Pi Runner 位于 Electron 主进程，负责领取、启动、取消和恢复 Agent 任务。它不直接访问业务服务、SQLite 或业务文件。

Pi 的业务工具只来自终端已注册的 MCP：

```text
Pi Agent
→ 官方 MCP 客户端
→ 现有 MCP stdio helper
→ Windows Named Pipe
→ CommandDispatcher
→ 唯一业务内核
```

这样可以继续保证：

- 人类界面和 Agent 使用同一业务语义；
- MCP 适配器不复制业务规则；
- 数据库与文件写入仍经过现有业务内核；
- `strategy.approve` 和 `approval.approve` 不向 Agent 暴露；
- Agent 的写操作继续执行版本、幂等、文件读回和错误规则。

## 5. 持久任务

复用现有 `tasks` 表和任务页面，不创建第二套任务中心。

新增任务类型 `agent.execute`。任务参数至少包含：

- 触发事件类型；
- 账号标识；
- 被批准或待处理对象的标识与版本；
- 固定的执行目标；
- 稳定幂等键；
- 创建时间。

Agent 的流式事件写入业务根目录：

```text
agent-runs/<task-id>/events.jsonl
agent-runs/<task-id>/result.json
```

数据库保存任务状态、进度、结果摘要、错误和上述文件的真实读回信息。不得把完整思维过程保存或展示；只保留用户可理解的动作、工具调用结果、产物和错误。

状态沿用现有任务状态：

- `queued`
- `running`
- `succeeded`
- `partial`
- `failed`
- `cancelled`
- `interrupted`

Pi 需要用户补充事实或人工批准时，任务以 `partial` 结束，并在结果中给出唯一明确的下一步，不伪装为仍在后台运行。

## 6. 触发规则

第一批触发规则：

1. `strategy.approve` 成功后，创建一个 `agent.execute` 任务，目标是依据新策略选择并完成当前最有价值的下一步。
2. 最终发布批准仍只授权确定版本；自动构建发布包可作为批准后的任务，但不得自动发布到平台。
3. 同一对象、同一版本和同一触发事件只能存在一个有效任务。
4. 业务批准成功但任务创建失败时，界面必须明确显示“策略已批准，但 Pi 任务创建失败”，不得回滚或隐瞒已经生效的人工决定。

批准完成后界面立即显示任务标识和当前状态，不再只显示“已保存”。

## 7. 登录与模型

默认模型来源可为用户本机 CockpitTools 聚合的订阅服务或用户填写的 OpenAI Responses 兼容 API；ChatGPT Plus/Pro（Codex）订阅登录继续作为可选来源。

发现与选择顺序：

1. 检查 Pi 自身凭据目录中是否已有有效的 OpenAI Codex 订阅登录；
2. 检查本机 Codex 凭据是否存在，只显示“检测到”及可用性，不展示令牌；
3. 当前 Pi SDK 能安全复用或导入时，经用户一次明确授权后写入 Pi 凭据存储；
4. 凭据格式不兼容、过期或刷新失败时，启动 Pi 官方浏览器 OAuth 或设备码登录；
5. 用户可导入本机 CockpitTools，或填写自定义接口地址、API Key 和模型。

不得假设 Codex 与 Pi 的凭据文件格式永久兼容。复用能力必须由真实登录调用验证，文件存在不等于登录有效。

API Key 使用 Electron `safeStorage` 调用 Windows DPAPI 加密后保存在应用配置目录。数据库和业务根目录只保存提供商、模型、认证方式、状态和最后验证时间，不保存密钥或令牌。

设置页提供：

- 当前执行内核：Pi；
- 认证方式与账号状态；
- 当前模型；
- 扫描已有登录；
- 登录或重新登录；
- 输入或更换 API Key；
- 测试连接；
- 最近一次失败及处理方式。

## 8. Skill 与上下文

每次 Agent 任务都加载项目已经安装的 `content-business-partner` Skill，并先调用：

1. `account.search`
2. `business.snapshot`
3. `business.pending`

任务输入只描述触发事实和目标，不把整个聊天历史复制给 Pi。终端对象和业务文件是正式上下文来源。

Pi 完成专项工作时可按 Skill 规则调用资讯、研究、写作和图片能力，但所有影响后续经营的事实和产物必须通过 MCP 写回终端并读回。

## 9. 界面

不新增一级导航。

现有“任务”页面增加 Agent 任务的自然中文名称、阶段、结果、失败和取消入口。“经营”及“发布包”页面在批准后显示：

```text
已批准，Pi 已开始执行下一步
任务：<自然中文名称>
状态：排队中 / 执行中 / 已完成 / 需要你处理 / 失败
```

用户可打开任务详情查看：

- 为什么触发；
- Pi 正在做什么；
- 已生成哪些终端对象和文件；
- 哪一步失败；
- 是否需要人工处理。

界面不显示内部提示词、原始令牌、思维过程或大段工具日志。

## 10. 取消、重启与并发

- 用户可以取消排队中或执行中的 Agent 任务。
- 取消必须停止后续工具调用，已成功写入的真实业务对象不删除。
- 应用启动时将遗留的 `running` Agent 任务标记为 `interrupted`，随后使用原任务标识恢复一次。
- 恢复依赖 MCP 写命令的幂等键，不重复创建业务对象或覆盖历史文件。
- 第一版每个业务根目录只运行一个 Pi 任务，避免凭据锁竞争和业务状态并发冲突。
- 新任务可以排队，但不能并行执行。

## 11. 错误

至少区分：

- `AGENT_AUTH_REQUIRED`：没有可用登录；
- `AGENT_AUTH_EXPIRED`：登录失效；
- `AGENT_MODEL_UNAVAILABLE`：模型不可用；
- `AGENT_MCP_UNAVAILABLE`：终端 MCP 不可连接；
- `AGENT_CANCELLED`：用户取消；
- `AGENT_INTERRUPTED`：应用退出或异常中断；
- `AGENT_EXECUTION_FAILED`：Pi 执行失败；
- 现有业务错误：保持原错误码和业务下一步。

错误必须进入任务记录和结果文件。认证失败不得反复自动重试或弹出多个登录窗口。

## 12. 验收

自动验收至少包含：

1. 批准策略后只创建一个 `agent.execute` 任务；
2. Pi 能发现终端 MCP，且发现不到两个人工批准工具；
3. 使用测试提供商运行一条确定性 Agent 链，真实创建并读回终端对象与文件；
4. 重复触发不重复创建任务或业务对象；
5. MCP 断开后任务明确失败；
6. 取消后不再继续调用工具；
7. 应用退出后任务进入中断状态，重开后恢复且不重复产物；
8. 没有登录时显示明确认证状态；
9. API Key 不出现在数据库、业务目录、日志或任务回执；
10. 真实 CockpitTools 或自定义兼容 API 完成一次模型与 MCP 人工链；
11. 真实 Windows 打包应用中批准后 Pi 自动执行并写回结果。

最终完成必须同时具备真实 Pi、真实 MCP、真实 SQLite、真实业务文件和安装应用证据。模拟提供商只用于自动回归，不能替代真实登录与真实模型验收。

## 13. 实施任务拆分

书面规格确认后，在唯一任务台账登记以下顺序任务：

1. `PI-001`：产品契约、依赖、认证探测和失败实验；
2. `PI-002`：持久 Agent 任务、Pi Runner、MCP 工具链和重启恢复；
3. `PI-003`：策略批准触发、任务与设置界面、取消和错误状态；
4. `PI-004`：真实订阅、真实安装应用和完整自动接力验收。

每次只允许一个任务处于 `in_progress`。`PI-004` 只做最终验收，发现功能缺口必须退回责任任务修复。
