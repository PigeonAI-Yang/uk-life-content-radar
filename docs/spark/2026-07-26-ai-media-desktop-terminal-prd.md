# AI（人工智能）+ 自媒体桌面终端 PRD（产品需求文档）

状态：用户已确认  
版本：第一版  
平台：Windows（微软桌面系统）  
日期：2026-07-26

## 1. 产品定义

本产品是一款本地优先的一站式自媒体桌面终端。

对人类用户，它提供浏览器、资料库、内容编辑器、素材库和发布包工具，支持从资讯发现到图文发布包导出的完整工作。

对 Codex（代码智能体），软件内全部业务操作均先定义为统一 API（应用程序接口），再通过 MCP（模型上下文协议）暴露。Codex（代码智能体）不依赖模拟鼠标点击，不需要软件内另建 AI（人工智能）聊天窗口。

界面与 MCP（模型上下文协议）是同一业务能力的两个入口，操作同一份数据，遵守相同状态规则，并产生相同文件、结果和错误。

## 2. 产品目标

第一版必须完成以下闭环：

1. 用户或 Codex（代码智能体）发现并收集网页、选中文本、图片和本地文件。
2. 用户可长期搜索、筛选、整理和复用资料、历史文案与素材。
3. 内容项目可引用资料和素材，但资料、内容、素材也可独立存在和管理。
4. 用户或 Codex（代码智能体）可编写公共草稿，并生成小红书、抖音、微信公众号三个平台的独立图文版本。
5. 图片可完成裁剪、缩放、压缩、平台尺寸转换和文字叠加，原图始终保留。
6. 用户批准某一确定内容版本后，软件生成真实、可预览、可复制、可人工发布的多平台发布包。
7. 人工界面链与纯 MCP（模型上下文协议）链产生一致的对象、状态和磁盘产物。

## 3. 非目标

第一版不包含：

- 软件内 AI（人工智能）聊天窗口或提示词市场。
- 自动发布、定时发布或模拟操作小红书、抖音、微信公众号。
- 视频剪辑、音频编辑或完整图层式图片编辑器。
- 云同步、多人协作、团队权限或远程控制。
- 平台阅读量、点赞量等数据的自动回流与分析。
- 自建互联网搜索引擎。
- 不可恢复的永久删除。
- macOS（苹果桌面系统）及其他桌面系统。

抖音第一版仅生成图文发布包，不承诺视频作品。

## 4. 产品原则

### 4.1 人类使用优先

产品首先必须是正常、顺手的自媒体桌面软件。API（应用程序接口）、MCP（模型上下文协议）、对象标识、去重、索引和任务执行属于底层契约，不主导日常界面结构。

### 4.2 能力对等

除窗口缩放、面板折叠、主题切换等纯界面行为外，任何创建、修改、归档、恢复、关联、检索、处理、审批请求和导出业务数据的界面操作，均须有语义等价的 API（应用程序接口）能力和 MCP（模型上下文协议）工具。

### 4.3 本地优先与存储透明

用户指定业务素材根目录。网页内容、原始图片、修改图片、外部文件和发布包保存在该目录；SQLite（本地数据库）只保存索引、元数据、关系和状态。

软件必须显示真实根目录、文件数量、占用容量和增长情况，不在用户不知情的系统盘位置长期保存业务文件。

### 4.4 长期可管理

一级导航不随主题、资料量或使用年限增长。签证、租房、银行、交通等业务主题只作为分类、标签、筛选或保存视图。

资料、历史文案和素材均支持独立检索、组合筛选、归档、恢复与跨项目复用。归档内容仍进入全局搜索。

### 4.5 不破坏历史

原始资料和原图永久保留。编辑生成新版本，不覆盖旧版本。第一版仅支持归档与恢复，不提供永久删除。

## 5. 用户与职责

### 5.1 人类用户

- 浏览、阅读和判断资讯价值。
- 修正分类、引用、文案和图片。
- 管理账号定位与内容风格。
- 审核确定版本并批准生成最终发布包。
- 查看 Codex（代码智能体）任务结果和可理解的失败原因。

### 5.2 Codex（代码智能体）

- 通过 MCP（模型上下文协议）收集、整理、分类和关联资料。
- 创建选题、草稿和平台版本。
- 调用图片基础处理能力并保存新版本。
- 创建预览和待批准发布包候选。
- 读取任务状态、对象状态、版本、关系、真实文件路径和错误。
- 不得绕过用户对最终发布包的版本绑定审批。

## 6. 一级产品结构

一级模块长期固定：

1. 工作台
2. 浏览与收集
3. 资料库
4. 内容
5. 素材库
6. 发布包
7. 账号
8. 任务
9. 设置

全局搜索贯穿全部模块。归档是对象状态，不是一级模块。存储信息位于设置；具体执行记录位于任务详情。

## 7. 核心业务对象

| 对象 | 用途 | 必须独立管理 |
| --- | --- | --- |
| 资料 | 已收藏网页、文章或其他外部信息 | 是 |
| 摘录与笔记 | 原文片段、用户笔记和来源上下文 | 是 |
| 素材 | 图片及其他本地文件 | 是 |
| 内容项目 | 一次选题或内容生产工作 | 是 |
| 文案版本 | 公共草稿、历史版本和平台版本 | 是 |
| 账号 | 账号定位、语气、平台身份和默认模板 | 是 |
| 发布包 | 已批准版本对应的真实导出产物 | 是 |
| 任务 | 长时间业务操作的状态与结果 | 是 |

每个对象必须拥有稳定标识。重命名、移动或归档不得改变标识。资料、内容和素材通过引用关联，不复制底层文件。

## 8. 核心使用流程

### 8.1 浏览与收集

1. 用户在内置浏览器使用现有网站或搜索服务查找资讯。
2. 用户可收藏当前网页、摘录选中文本、保存页面图片、下载文件或写临时笔记。
3. 收集时可直接加入内容项目，也可先进入资料库或素材库。
4. 再次收集相同网址时，软件提示已有资料，允许关联现有资料或继续保存更新内容。
5. Codex（代码智能体）可通过 MCP（模型上下文协议）完成相同收集动作。

第一版不自建互联网搜索引擎。软件内搜索只搜索本地已收集资产。

### 8.2 资料管理与找回

1. 全局搜索覆盖资料、摘录、笔记、历史文案、素材元数据、发布包和账号。
2. 结果可按对象类型分组或切换，避免全部混成单一卡片流。
3. 支持关键词、语义、主题、地区、人群、来源、时间、账号、平台、状态和自由标签组合筛选。
4. 用户可保存常用筛选视图；保存视图位于对应业务库内，不污染一级导航。
5. 资料列表至少显示摘要、来源、时间、主题、使用状态和关联内容。
6. 归档资料默认可隐藏，但仍可被全局搜索找到并恢复。

### 8.3 内容创作与引用

1. 用户可从内容模块创建选题或从历史文案创建新版本。
2. 编辑器可按需展开资料和素材面板，同时资料库和素材库保留独立完整页面。
3. 用户可将资料、摘录和素材加入内容项目，不复制底层对象。
4. 引用资料时保留来源关联，不强制显示为学术脚注。
5. 点击引用可回看原文片段及其上下文。
6. 历史文案可按账号、平台、主题、时间、状态和关键词搜索。
7. 从历史文案创建新内容时，保留来源版本关系。
8. 公共草稿可生成三个平台版本；平台版本允许独立人工修改，重新生成不得静默覆盖人工编辑。

### 8.4 素材管理与图片处理

1. 素材库支持图片和外部文件导入、搜索、筛选、归档、恢复和跨项目引用。
2. 图片显示来源、说明、尺寸、文件大小、真实位置、使用记录、原图和编辑版本。
3. 支持裁剪、缩放、压缩、平台尺寸模板和文字叠加。
4. 文字叠加至少支持文字内容、字体、字号、颜色、位置和再次编辑。
5. 每次处理生成新版本并保留原图。
6. 可从外部图片工具导入修改结果，并关联回原素材。
7. 各平台独立保存图片顺序和尺寸版本，修改一个平台不得破坏其他平台。

### 8.5 发布包

1. 内容项目可先生成三个平台的预览候选。
2. 用户批准必须绑定内容项目、目标平台、正文版本和图片版本。
3. 正文、图片或顺序发生变化后，旧批准自动失效。
4. Codex（代码智能体）可以请求批准，但不能自行完成最终批准。
5. 批准后生成真实目录和文件；用户可打开目录、复制文本并按顺序取图。
6. 应用内预览、发布包清单和磁盘内容必须一致。

第一版平台产物：

| 平台 | 文本产物 | 图片产物 | 其他产物 |
| --- | --- | --- | --- |
| 小红书 | 标题、正文、话题标签 | 封面、正文图片、顺序和平台尺寸版本 | 预览、来源清单、审核记录 |
| 抖音 | 标题或说明、正文、话题标签 | 封面、图文图片、顺序和平台尺寸版本 | 预览、来源清单、审核记录 |
| 微信公众号 | 标题、摘要、正文 | 封面、正文插图、顺序和平台尺寸版本 | 长文预览、来源清单、审核记录 |

第一版不承诺公众号后台富文本无损粘贴。

## 9. 模块需求

### 9.1 工作台

- 显示最近使用、继续创作、待处理资料、待审核候选、失败任务和 Codex（代码智能体）当前业务任务。
- 不承担完整资产浏览，不随资料数量增长而扩张栏目。

### 9.2 浏览与收集

- 提供多标签内置浏览器、地址栏、网页内查找和正常网站登录态。
- 支持当前网页、选中文本、图片和下载文件四种收集入口。
- 收集后明确显示进入的资料库、素材库或内容项目。

### 9.3 资料库

- 独立管理资料、摘录和笔记。
- 支持全文搜索、语义搜索、组合筛选、排序、保存视图、关联内容、归档和恢复。
- 详情页以阅读和使用为主；仅在必要时提示已有收藏、内容更新或疑似重复。

### 9.4 内容

- 独立管理选题、公共草稿、历史版本和平台版本。
- 支持写作时查看资料、引用上下文、调用素材和创建新版本。
- 不把用户锁进固定线性阶段，允许在资料、写作、图片和平台版本之间往返。

### 9.5 素材库

- 独立管理原图、编辑版本和外部文件。
- 提供搜索、筛选、使用记录、基础图片处理和版本回看。
- 采用人类可理解的“原图、编辑版本、用于哪些内容”语言，不在主界面暴露内部哈希或数据库结构。

### 9.6 发布包

- 统一查看待批准、已导出和失效候选。
- 展示三个平台的正文、图片顺序、预览、来源和审核状态。
- 导出后提供打开真实目录与复制文本入口。

### 9.7 账号

- 管理账号名称、定位、受众、语气、禁用表达、平台身份和默认内容模板。
- 全局资料和素材可被多个账号引用；内容与发布包归属指定账号。

### 9.8 任务

- 展示 Codex（代码智能体）和用户触发的长任务状态、进度、结果与可理解错误。
- 不是聊天窗口，不展示 Codex（代码智能体）的逐步推理。
- 支持查看待执行、运行中、成功、部分成功、失败和取消状态。

### 9.9 设置

- 设置并显示业务素材根目录。
- 显示真实文件数量、占用容量和增长情况。
- 管理平台尺寸模板、默认导出目录和语义搜索索引状态。

## 10. API（应用程序接口）与 MCP（模型上下文协议）契约

### 10.1 总体要求

- 所有业务写操作返回新对象、稳定标识、当前版本或更新时间和新状态，不能只返回“成功”。
- 写后可按稳定标识读回对象、关系、真实文件路径和状态。
- MCP（模型上下文协议）是统一业务 API（应用程序接口）的薄适配层，不复制业务逻辑。
- 界面关闭时，Codex（代码智能体）仍可执行无需用户即时交互的业务命令；重新打开界面后可看到相同结果。

### 10.2 第一版能力矩阵

| 业务域 | 必须开放的业务能力 |
| --- | --- |
| 浏览收集 | 收集网页、摘录文本、保存图片、导入文件、写笔记、关联内容项目 |
| 资料 | 创建、读取、更新、搜索、筛选、保存视图、归档、恢复、关联内容 |
| 内容 | 创建选题、写入草稿、创建版本、读取历史、关联或移除资料与素材、生成平台版本 |
| 素材 | 导入、读取、搜索、归档、恢复、裁剪、缩放、压缩、尺寸转换、文字叠加、保存版本 |
| 发布包 | 创建预览候选、读取清单、请求批准、读取批准状态、生成并导出已批准版本 |
| 账号 | 创建、读取、更新账号定位、风格和平台配置 |
| 任务 | 创建长任务、读取状态与进度、读取结果与错误、取消允许取消的任务 |
| 设置 | 读取和设置业务根目录、读取容量与文件数量、读取索引状态 |

### 10.3 错误契约

错误至少区分：

- 对象不存在
- 版本冲突
- 输入格式错误
- 文件不可读或不可写
- 任务失败
- 最终版本未批准
- 批准因内容变化而失效

批量操作必须分别返回成功项与失败项。部分成功不得表述为整体成功，也不得留下被标记为完整的残缺发布包。

### 10.4 长任务

网页收集、图片处理、全文与语义索引、预览生成和多平台打包可返回任务标识。应用重启后仍能查询任务最终状态、结果对象和错误。

### 10.5 幂等与重复执行

创建、导入、采集、图片处理和打包命令接受调用方提供的幂等键。相同键与相同参数重复提交返回同一结果；相同键但参数不同明确报冲突。

普通文字编辑不强制使用幂等键，以对象版本避免静默覆盖。

## 11. 搜索与规模要求

### 11.1 搜索能力

- 全文搜索是默认入口。
- 语义搜索用于用户记不清准确关键词时的相似内容发现。
- 固定核心维度包括主题、地区、人群、平台、内容类型和状态。
- 自由标签用于临时热点和细分语义。
- 搜索结果支持分页、稳定排序、对象类型分组和保存视图。

### 11.2 规模验收数据

第一版使用以下本地测试数据验收长期可管理性：

- 100,000 条资料、摘录和笔记
- 30,000 个图片及编辑版本
- 5,000 篇历史文案与平台版本
- 1,000 个发布包
- 20 个账号

在 Windows 11（微软桌面系统）、16GB（十六吉字节）内存的参考设备上：

- 关键词加组合筛选的首屏结果在 2 秒内出现。
- 语义搜索首屏结果在 5 秒内出现。
- 搜索翻页保持稳定顺序，不遗漏或重复同一对象。
- 查找旧资料、旧文案和已使用素材不要求用户逐页遍历全部数据。

## 12. 存储与数据正确性

- 业务素材根目录由用户首次使用时选择，之后可在设置中查看。
- SQLite（本地数据库）不保存大体积业务文件本体。
- 每个文件型对象可读回真实绝对路径、大小和修改时间。
- 导入或生成失败时，不得留下状态为“完成”的残缺对象。
- 软件不自动删除原始资料、原图或归档内容。
- 临时文件在任务成功或失败后必须有明确结果，不得无限积累为隐藏业务存储。

## 13. 验收场景

### 13.1 人工完整链

用户仅通过界面完成：

浏览网页 → 收藏网页与摘录 → 加入内容项目 → 引用资料写作 → 选择并编辑图片 → 生成三个平台预览 → 批准确定版本 → 导出发布包 → 打开真实目录并人工取用。

### 13.2 MCP（模型上下文协议）完整链

Codex（代码智能体）不点击界面，仅通过 MCP（模型上下文协议）完成同一链中的收集、整理、写作、图片处理和预览生成。用户完成最终批准后，Codex（代码智能体）生成并读回发布包清单。

### 13.3 双入口一致性

同一业务操作分别通过界面与 MCP（模型上下文协议）执行后，产生同构对象、状态、版本、关系、错误和磁盘文件。

### 13.4 审批门禁

- 未批准时生成最终发布包必须失败。
- 批准指定正文与图片版本后可成功。
- 批准后修改正文、图片或顺序，旧批准必须失效。

### 13.5 失败与重启

- 人工取消素材根目录写权限后执行导入，必须返回明确文件写入失败，且不得留下“已完成”素材。
- 中断图片处理或打包任务并重启应用，任务不得显示成功，且仍可查询错误或未完成状态。
- 多平台打包中任一文件失败时，返回失败平台和文件，不得返回完整成功。

### 13.6 长期管理

- 在规模验收数据中，通过关键词、语义、主题、来源、时间、账号、平台和状态组合找到指定旧资料、历史文案和素材。
- 从历史文案创建新版本后，仍可反查原资料、原素材和被人工修改过的平台版本。
- 同一资料与素材可被多个账号和内容项目引用，不复制底层文件。
- 归档对象仍可全局搜索并恢复。

### 13.7 存储一致性

- 设置中显示的根目录、文件数量和占用容量与真实磁盘一致。
- 发布包清单中的每个文件真实存在，文件顺序、尺寸和应用预览一致。

## 14. 第一版完成定义

只有以下条件全部满足，第一版才算完成：

1. 人工完整链通过。
2. MCP（模型上下文协议）完整链通过。
3. 双入口一致性通过。
4. 审批门禁通过。
5. 长期规模检索通过。
6. 三个平台图文发布包的真实磁盘产物通过。
7. 存储路径、数量和容量读回通过。
8. 所有失败、部分成功、降级或跳过检查均被明确报告。
